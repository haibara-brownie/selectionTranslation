# 架构

给刚接手代码的人（或 AI）看的一张地图：**代码为什么长成这样**。
「怎么用」在 [`README.md`](../README.md)，「怎么发版」在 [`发版.md`](发版.md)，
「GTK 版什么时候删」在 [`切到-tauri-版.md`](切到-tauri-版.md)。

## 一、三层

```
crates/seltrans-core/     业务逻辑，不依赖任何 GUI 工具包
  │                       配置 / 预设 / 大模型调用 / 取词 / 日志 / 配色 / 字体
  ├── src/                GTK4 界面层    → 二进制 seltrans        （遗留，迁移 P5 后删）
  └── src-tauri/ + ui/    Tauri 界面层   → 二进制 seltrans-tauri  （在建）
```

界面层已经换过一次，**默认它还会再换**。所以：

- 往 core 里加东西前先问一句「mac 和 Windows 上这段还成立吗」。平台相关的四件事
  （取词、托盘、快捷键、自启）不属于 core。
- `src-tauri/src/cmds.rs`、`settings_cmds.rs` 只做**搬运和错误转字符串**，
  任何业务判断（该用哪个供应商、什么算空输入、提示词怎么渲染）都在 core。
  下次换界面时这两个文件应该可以整个丢掉。
- 配色（`palette.rs`）、字体分档（`typography.rs`）也在 core —— 两个界面层用同一组
  色和同一张 `CJK_RANGES` 表，抄两份必然漂移。

两个二进制**共用同一份 `~/.config/seltrans/config.json` 和同一个日志文件**，
可以随时来回切，这是迁移期能安心试用的前提。

## 二、三条决定了代码形状的硬约束

看代码时如果觉得某处「绕」，多半是撞上了这三条里的一条。

### 1. 取词必须赶在窗口拿到焦点之前

模拟出来的复制键（Ctrl+C / ⌘C）发给的是**当前有焦点的窗口**。译文窗口一旦抢到焦点，
复制到的就是我们自己界面上的东西，用户选的那段再也拿不到了。

所以时序是「**Rust 先取词 → 再开窗 → 前端拿到的是结果**」，不是「开窗后让前端去取」。

- 取词入口：`src-tauri/src/windows.rs::prepare`
- 调用点在 `main.rs` 里，**位于 `tauri::Builder` 之前**
- 前端拿到的 `TranslateRequest.text` 已经是取好词的结果；取不到时带 `error` 过来，
  界面显示原因并让用户手输

Linux 的主选区那条路不受焦点影响，但兜底的 Ctrl+C 一样受，不能只照顾前者。

### 2. Wayland 下应用注册不了全局快捷键

协议层就没有这个接口。Tauri 的 global-shortcut 插件底层是 `global-hotkey`，
Linux 路径纯 X11；tao 检测到 Wayland 时直接不启动快捷键线程 —— 注册会「成功」，
但回调**永远不触发**（tauri#3578，上游长期未决）。

Linux 上走的是另一条路：

```
用户按 Mod+Shift+T
  → 合成器（niri）spawn 一个新进程            data/niri-snippet.kdl
  → 新进程解析 argv，交给 single-instance 插件
  → 常驻实例收到 argv，重新解析一遍            main.rs 的 plugin 回调
  → windows::dispatch 派活，新进程退出
```

**这就是 `main.rs` 里 argv 被解析两次的原因**（`parse()` 在 `main` 里调一次、在
single-instance 回调里再调一次），不是冗余。

mac / Windows 才由 `hotkey.rs` 自己注册（Carbon / `RegisterHotKey`）。
Linux 分支刻意什么都不做、只记一行日志 —— 注册一个「注册得上但永不触发」的快捷键
会让日志和设置界面显得一切正常，用户按了没反应却查不出原因。

### 3. 无窗口子命令必须在 Tauri 初始化之前跑完并退出

`translate` / `log` / `autostart` 一旦进了 Tauri，argv 会被 single-instance 转交给
常驻实例、本进程立刻退出 —— 那时候 `seltrans-tauri translate --text hi` 的行为就变成
「让常驻实例弹个窗口」，而不是「在终端打印译文」。

所以 `headless.rs` 在 `tauri::Builder` 之前就地了结这几个子命令。
`--help` / `--version` 更靠前。

## 三、分层边界与几个刻意的选择

| 位置 | 做法 | 为什么 |
|---|---|---|
| `state.rs::UiState` | 首屏要的东西**一个命令拿全** | 窗口是按快捷键弹的，多一次 IPC 往返就多一分肉眼可见的延迟 |
| `cmds.rs::translate` | 流式走 `tauri::ipc::Channel` | 全局事件会广播到所有窗口，同时开着弹窗和设置页会串台 |
| `windows.rs` | 常驻模式下关窗口**只藏不销毁** | 新建 webview 要几百毫秒，划词翻译最忌讳这个 |
| `windows.rs` | 复用窗口时才发 `seltrans://translate` 事件 | 首次创建时前端会主动调 `launch_args` 去取，那会儿它还没挂上监听器 |
| `main.rs` | 用 `launch_args` 命令传首屏文本，不走 URL 参数 | 待翻译文本可能很长、可能带任意字符，塞进 URL 要转义两次，出问题极难排查 |
| `main.rs` | Linux 上显式 `glib::set_prgname` | 合成器靠 Wayland app-id 匹配窗口规则，而 GTK 取的是二进制名，会变成 `seltrans-tauri`，niri 规则一条都匹配不上 |
| `llm.rs` | 刻意**不发送** `temperature` | Claude 当前世代模型收到会直接 400；需要的话在供应商配置的「附加请求体」里自己加 |
| `presets.rs` | 只提供 `base_url`，**不写死模型名** | 各家迭代太快，模型列表一律点「拉取模型」实时从 `/v1/models` 取 |

### 前端（`ui/`）

原生 DOM，无框架，两个入口对应两个窗口（`index.html` = popup，`settings.html`；
在 `vite.config.ts` 的 `rollupOptions.input` 里配着）。

- **`ui/lib/api.ts` 是前端唯一的 IPC 出口。** 散着写 `invoke("...")` 的话，
  命令改名时 TypeScript 一点忙都帮不上。里面的类型和 Rust 侧 `#[derive(Serialize)]`
  一一对应（Rust 那边是 `rename_all = "camelCase"`）。
- **设置页的配置只有一份，在内存里**（`ui/lib/shell.ts` 的 `ctx.config`）。
  各页直接改这个对象、调 `ctx.save()`（防抖 250ms）。
  **切页 / 关窗之前必须 `ctx.flush()`** —— 不然最后一次改动还在定时器里，直接丢。
- 前端不做业务判断。渲染 Rust 给的状态、把操作转成命令、把流式事件贴到译文区，
  就这三件事。

## 四、平台分叉在哪

| 关注点 | Linux / Wayland | macOS | Windows |
|---|---|---|---|
| 取词首选 | 主选区 `wl-paste --primary` | 辅助功能 API `kAXSelectedTextAttribute` | 无通用接口 |
| 取词兜底 | 模拟 Ctrl+C（ydotool） | 模拟 ⌘C | 模拟 Ctrl+C |
| 快捷键 | 合成器（`data/niri-snippet.kdl`） | 应用自己注册 | 应用自己注册 |
| 托盘 | `ksni`（纯 Rust + 纯 D-Bus） | Tauri 内置 tray-icon | Tauri 内置 tray-icon |
| 自启 | XDG autostart `.desktop` | LaunchAgent | 注册表 |
| 日志位置 | `$XDG_STATE_HOME/seltrans` | `~/Library/Application Support/seltrans` | `%LOCALAPPDATA%\seltrans` |

分叉靠 `src-tauri/Cargo.toml` 的 `[target.'cfg(...)'.dependencies]` 分段实现：
`tray-icon` / `global-shortcut` 只在非 Linux 段打开，**Linux 构建根本不会把
appindicator 和 global-shortcut 链进来**。Linux 不用 Tauri 内置托盘是因为它走
libayatana-appindicator，Wayland 下 `.deb` 安装和 dev 模式图标根本不显示
（tauri#14234）；ksni 在这台 niri 机器上实测能用。

### 改取词代码时必须守的一条

**兜底路径发复制键之前，必须先显式抬起所有修饰键，且无论中途出什么岔子都要再抬一次。**

用户按快捷键的那一刻手还按着 `Mod+Shift`，这时候直接发 Ctrl+C，应用收到的是
`Super+Shift+Ctrl+C` —— 复制不到东西，还可能把合成器的修饰键状态搞乱（表现为键盘
「卡住」，Linux 上真踩过一次，整台电脑没法操作）。别因为「那个平台好像没这个问题」
就省掉。

剪贴板还原只还原纯文本，富文本和图片还不回去，这是已知取舍。

## 五、跑起来 / 查一遍

```bash
pnpm install                    # 首次
pnpm tauri dev                  # 开发（自动起 vite dev server）
pnpm build                      # 前端：tsc --noEmit && vite build

cargo test  --workspace --exclude seltrans
cargo clippy --workspace --exclude seltrans --all-targets -- -D warnings
cargo fmt --all --check
cargo test -p seltrans-core <test_name>          # 单个测试
```

三个坑，栽过不止一次：

1. **`--workspace` / `--all` 不能省。** 仓库根 `Cargo.toml` 既是 workspace 根
   又是一个 package，裸跑 `cargo test` / `clippy` / `fmt --check` 只作用于根包，
   其他 crate 被**静默跳过还报 ok**。
2. **根 package `seltrans` 是 GTK4 版，只在 Linux 且 gtk4 ≥ 4.18 / libadwaita ≥ 1.7
   的环境上编得过**（`Cargo.toml` 开了 feature `v4_18` / `v1_7`，system-deps 会在构建期
   硬卡版本）。mac、Windows、ubuntu-24.04 上一律加 `--exclude seltrans`。
   CI 为此分了两个 job，理由见 [`发版.md`](发版.md#为什么-ci-要分两个-job)。
   迁移 P5 删掉 GTK 代码之后，这个 `--exclude` 和那个 job 一起消失。
3. **pnpm 必须是 11。** `pnpm-workspace.yaml` 用的 `allowBuilds` 是 pnpm 11 才认的键，
   装成 10 会被当未知配置忽略、esbuild 的安装脚本被拦，`vite build` 报二进制缺失。
   这个键名随 pnpm 版本变过两次，升级时留意。

测试都是集成测试，在 `crates/seltrans-core/tests/`（palette / sse / system_fonts /
typography），共 28 个，没有内联单测。前端目前没有测试基建。
