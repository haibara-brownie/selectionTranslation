# ADR 0001：按字符脚本分配字体

- 状态：已采纳
- 日期：2026-08-20
- 相关：`crates/seltrans-core/src/typography.rs`、`src/fonts.rs`、`crates/seltrans-core/tests/typography.rs`

## 背景

字体设置分三档：拉丁字体、中文字体、后备字体。

直觉做法是把三档串成一个字体栈，靠 CSS / Pango 的逐字符回退自动分配。**这个做法是错的**，
因为回退规则是「列表里第一个有该字形的字体就赢」。而 JetBrains Maple Mono、Sarasa Gothic
这类流行的编程字体**自带汉字**，把它选成拉丁字体（第一档）之后，汉字也会被它接管，
用户明明选了思源宋，界面上却是等宽汉字 —— 「中文字体」那一档等于不存在。

## 决定

不靠回退顺序，**两档各自钉死在自己的字符区间**。

区间表 `CJK_RANGES` 是单一事实源，两个界面层都从它派生：

- **GTK 版**：`GtkTextTag` 给文本区的汉字范围指定 family；界面上的 Label 遍历控件树挂
  Pango 属性（属性索引是**字节**偏移，不是字符）。
- **Tauri 版**：两个 `@font-face`，中文档 `unicode-range` 取该表、拉丁档取该表的**补集**，
  字体栈为 `中文档, 拉丁档, 后备档, system-ui, sans-serif`。

只填了拉丁字体、没填中文字体时**不做任何限制**，让它管全部字符 —— 用户没表达过
「汉字要用别的字体」的意思，这时候限制它等于替用户做了没被授权的决定。

## 否掉的方案

**只限制拉丁档（列一个拉丁区白名单）。** 最早的探针验的就是这版，能work。但白名单必须
穷举「非汉字」的所有区间 —— 西里尔、希腊、阿拉伯、符号、箭头、emoji…… 漏一个，那类
字符就会掉进后备档。维护成本高且注定漏。

**只限制中文档。** 这是第二版，看起来更简洁：只有中文档带区间，拉丁档完全放开。
实机才发现它漏了一半 —— `unicode-range` 只决定「哪个字体**有资格参与**」，被选中的
字体真缺字形时，浏览器仍会继续往后回退，而下一档正是拉丁档，于是自带汉字的 Maple
又赢了，绕一圈回到原来的 bug。

触发这个漏洞的不是构造出来的边角情况：用户把中文字体填成了 `HarmonyOS Sans`，
而那是**纯拉丁族**，带汉字的是 `HarmonyOS Sans SC`。

所以最终采用两档都限制。代价是两档都缺字形时汉字落到通用族（系统默认字体），
不见得漂亮，但至少是真的汉字。

## 后果

- 加一个字符区间只要改 `CJK_RANGES` 一处，两个界面层自动跟上；
  `tests/typography.rs` 会盯着「`is_cjk` 的判定」和「CSS 里声明的区间」不许漂移。
- **设置界面应当校验中文字体是否真的含汉字**，选到纯拉丁族时给出警告。
  这一条还没做（Tauri 版设置页属于迁移的 P2），是已知缺口。
- 浏览器里的实际渲染没法用单元测试覆盖，只能靠 `.scratch/tauri-migration/` 下的
  探针在真实 WebKitGTK 里量字符宽度。改动字体策略时请重跑探针，别只看单测绿。
