# 新手引导（分步指引）

## 为什么

T-13 做的是一张**静态卡片**：告诉你有哪些快捷键，然后就没了。
它解决不了「小白装完不知道怎么配」—— 那是本程序真正的门槛：
一个供应商都没有的时候，按什么键都翻不出东西。

要的是**跨窗口的分步指引**：从弹窗一路带到设置窗口，把供应商配完，再带回弹窗。

## 设计

### 步骤（7 步）

| # | 窗口 | 锚点 | 说的话 |
|---|---|---|---|
| 1 | 弹窗 | 无（居中大卡片） | 这是什么、能干什么。`[下一步]` / `[我会用]` |
| 2 | 弹窗 | ⚙ 按钮 | 「设置在这儿」，点它就进下一步 |
| 3 | 设置·供应商 | 「添加」按钮 | 「点它，挑一家预设」 |
| 4 | 设置·对话框 | API key 输入框 | 「base_url 已经填好了，你只要补这个」 |
| 5 | 设置·对话框 | 「拉取模型」 | 「点它，从服务端实时取一份模型列表」 |
| 6 | 设置·对话框 | 「测试连接」 | 「发一条最短的请求，确认通了」 |
| 7 | 弹窗 | 无（居中） | 「配好了，选中文字按 <快捷键>」`[开始用]` |

### 三条约束

1. **快捷键一律取自后端**（沿用 T-13 的约束）。三平台不同、用户能改，写死就是教错人。
2. **不挡住功能**。指引气泡是浮层，底下的按钮照常能点 —— 用户点了真的控件就自动前进，
   不必非得点「下一步」。两条路都通。
3. **状态存在后端**，否则跨不了窗口。`Config.tour_step` 持久化，
   关掉程序再打开能接着走。

### 为什么状态必须持久化而不是内存

引导要跨两个窗口，而这两个窗口是**各自独立的 webview**，没有共享内存。
而且第 3～6 步用户会在设置窗口里操作很久，中途完全可能关掉弹窗。
存 `Config` 里既解决跨窗口，也顺带解决「装完先关了，第二天再打开」。

## 锚点怎么定位

气泡挂 `document.body` + `position: fixed`，按锚点的 `getBoundingClientRect()` 算位置
—— 和自绘下拉同一套路子（就地绝对定位会被祖先的 `overflow: hidden` 裁掉，
`6b7d5a1` 那次已经踩过）。

第 4～6 步的锚点在**对话框里**，打开引导时还不存在。所以要能**等元素出现**
（轮询 + 超时），等不到就跳过这一步而不是卡死。
