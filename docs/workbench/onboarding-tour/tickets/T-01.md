把 T-13 那张静态卡片换成七步的跨窗口指引。设计见 [spec.md](../spec.md)。

## 做了什么

| 位置 | 内容 |
|---|---|
| `config.rs` | `Config.tour_step: u32` |
| `cmds.rs` | `tour_step()` / `set_tour_step()`；已完成时返回 `u32::MAX` |
| `ui/lib/tour.ts` | 引擎：锚点定位、等元素出现、翻边、跨窗口交接 |
| `ui/lib/tour-steps.ts` | 七步的定义，两个窗口共用一份 |
| `ui/tour.css` | 气泡、箭头、被指控件的光晕 |
| `ui/settings/providers.ts` | 四个稳定 id 作锚点（`tourAnchor()`） |

## 三个实现要点

1. **气泡挂 `document.body` + `position: fixed`**，位置按锚点 rect 算。就地绝对定位
   会被祖先的 `overflow: hidden` 裁掉 —— 自绘下拉那次踩过（`6b7d5a1`）。
2. **不做成模态。** 只给被指的控件描一圈光晕，不加遮罩；底下的按钮照常能点，
   用户点了真的控件就自动前进，不必非得点「下一步」。
3. **锚点用稳定 id**，不用 `.rows > .row:nth-child(2)` 这种位置选择器 —— 中间加一行
   就指错地方。

## 实机验收（Arch，干净配置模拟新用户）

- ✅ 第 1 步居中大卡片，`1 / 7`，`跳过` / `下一步`
- ✅ 第 2 步齿轮被光晕圈住、气泡带箭头指向它，快捷键是**后端给的本平台值**
  （`Mod+Alt+T`），按钮文案变成「打开设置」
- ✅ **跨窗口交接**：点「打开设置」后设置窗口自动开在「供应商」页，
  引导在新窗口里接上第 3 步，`tour_step = 2` 落盘
- ✅ 第 3 步指向「添加」按钮
- ✅ **第 4 步等到了对话框里的锚点** —— 点「添加」→ 选 DeepSeek 之后，
  气泡指向 API Key 行，`4 / 7`。这一步的锚点在引导启动时根本不存在，
  靠 `MutationObserver` 等出来的
- ⬜ 第 5、6、7 步没逐个点过。它们和第 4 步是同一套机制、锚点是同一个对话框里的
  兄弟节点（截图里 `拉取模型` / `测试连接` 两个按钮都在），风险低但没验就是没验

## 修掉的一个 bug（实机才发现）

**锚点被移出 DOM 时，气泡留在原地指着空气。** 切到别的标签页、关掉对话框都会触发。
加了 `MutationObserver` 盯着锚点脱落，脱落就重跑这一步；重跑时给 10 分钟的等待
时限（用户可能去别处逛一圈再回来），而不是首次进入那个短时限。
实测：切走 → 气泡消失；切回 → 气泡自己回到「添加」旁边，步数还是 `3 / 7`。

## 一处观感修正

对话框里那三步原本 `placement: "top"`，气泡正好压在「名称 / 接口类型 / base_url」
三行上 —— 而第 4 步说的正是「这三样都替你填好了」，盖住它们自相矛盾。
改成 `"right"`：对话框 620px、窗口 900px，右边放得下。

## 已知限制

- 引导只在 Tauri 版里有，GTK 版没有（那边已经不再维护）。
- 第 3～6 步依赖设置页的四个 id。**改 `providers.ts` 时别把 `tourAnchor()` 删了** ——
  删了引导会在那一步等超时然后跳过，不会报错，很难发现。
