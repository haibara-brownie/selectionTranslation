在 Arch 上真打了一次 Linux 包并跑起来。`pnpm tauri build` 出 deb / rpm / AppImage。

## 结果

| 产物 | 大小 | 结论 |
|---|---|---|
| `seltrans_0.3.0_amd64.deb` | 6.7 MB | ✅ 依赖声明正确、二进制能跑 |
| `seltrans-0.3.0-1.x86_64.rpm` | 6.7 MB | ✅ 同上（未逐项验，与 deb 同一个二进制） |
| `seltrans_0.3.0_amd64.AppImage` | 99 MB | ⚠️ 能跑，但**跑在 XWayland 上**，见下 |

deb 的 `Depends: libwebkit2gtk-4.1-0, libgtk-3-0` 是对的 —— 那是 **Tauri 的 webview
宿主**，不是我们的界面。对照 `ldd`：

```
Tauri 版 seltrans-tauri：libwebkit2gtk-4.1 + libgtk-3 + libjavascriptcoregtk
老 GTK 版 seltrans     ：libadwaita-1 + libgtk-4
```

连 GTK 大版本都不一样。Tauri 版一个 libadwaita 都没链，`libgtk-3` 纯粹是 WebKitGTK
的开窗层；mac 上对应的角色是 AppKit，在系统里所以看不见这一行。

## 两个坑

### 1. AppImage 在 Arch 上打不出来：linuxdeploy 的 strip 太老

```
ERROR: Strip call failed: .../strip: libxxx.so: unknown type [0x13] section `.relr.dyn'
```

`.relr.dyn`（SHT_RELR）是较新的 ELF 特性，Arch 的工具链会生成，而 linuxdeploy 自带的
`strip` 不认，于是它 strip 每一个系统库都失败、整个 bundling 挂掉。

**绕法**：`NO_STRIP=1`。本机手工重跑那一步就成功了。

**但更该记住的是**：AppImage 本来就该在**你想支持的最老发行版**上打（glibc 只能向前
兼容），在 Arch 上打出来的只能在同样新的机器上跑。CI 用 ubuntu-24.04，那才是正确位置
——v0.2.0 那次 CI 的 Linux job 是过的，说明 ubuntu 上没这个问题。

### 2. AppImage 跑在 XWayland 上，app-id 首字母会变大写

linuxdeploy 的 GTK 插件往 AppRun 里硬塞了：

```sh
export GDK_BACKEND=x11 # Crash with Wayland backend on Wayland - ... tauri#8541
```

于是那份包不走原生 Wayland。X11 下窗口身份来自 WM_CLASS，GDK 把程序名首字母大写
当 class，app-id 就成了 `Xyz.brownie.SelectionTranslation`。
deb / 直接跑二进制都是原生 Wayland、全小写。

**结果**：`data/niri-snippet.kdl` 里那两条按 app-id 匹配的规则对 AppImage 全部失效，
弹窗被当普通窗口平铺。

**已修**：规则正则加 `(?i)`，一条同时管住两种。改完实测 AppImage 的弹窗
`floating=True size=[560,480]`，渲染、翻译、字体、下拉都正常。

> 这条比大小写本身更值得留意：**AppImage 用户拿到的是 XWayland 体验**，
> 不是原生 Wayland。HiDPI 缩放、输入法这些都可能和 deb 不一样。
> 想要原生 Wayland 就装 deb / rpm，或直接跑二进制。

## 没做的

- **没在真 Debian/Ubuntu 上 `dpkg -i` 装过。** 本机是 Arch，只做了解包 + 跑二进制 +
  查 control 的依赖声明。真装一遍要在 Ubuntu 上。
- rpm 只确认了产物存在，没解包验。
