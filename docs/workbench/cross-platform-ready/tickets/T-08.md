`tray.rs` 里 `icon_as_template(false)`，注释已说明原因：现有图标是彩色的、alpha 几乎是满的，
切成模板会变成两坨看不出内容的黑块。需要另配一张单色图 `icons/tray-mono.png`，
再把非 Linux 分支改成 `icon_as_template(true)`。

深色菜单栏里彩色图标很突兀，这是 mac 上最后的打磨项。

**验收**：mac 真机截图，浅色和深色菜单栏下图标都清晰、跟系统其他图标观感一致。

## 已完成（2026-08-20）

没有按票里设想的「另配一张 tray-mono.png」，而是**新增单色 SVG + 现场光栅化**：
`data/tray-mono.svg` 里把字形挖成洞（mask 涂黑），mac 上用 resvg 光栅化成 RGBA 喂给
Tauri 的 `Image::new_owned`，`icon_as_template(true)`。

理由：几何数据已经在 SVG 里了，再烤一张 PNG 进仓库就是两个事实源，改图标时必然漏改
一个。Linux 那边（ksni）本来就是现场光栅化的，用的同一套 resvg，只是终点从 SNI 的
ARGB 换成 Tauri 的 RGBA。为此把 resvg 从 Linux 专属改成 linux+macos 共用。

单色化还有一处不能省：两只气泡在彩色版里靠色相区分，单色下会糊成一块。前面那只先挖一圈
比自己大 1.6 的缝再画本体，两只之间就有了分隔线。

### 验证状态

- **光栅化：已验证。** 新增单测 `单色托盘图标要有内容也要有镂空`，同时卡住两头：
  不透明像素太少（画成空白）和透明像素太少（mask 没生效 → 菜单栏上一坨黑块）。
  这两种失败在菜单栏上都很难看出来，只会表现成"图标不见了"或"图标很怪"。
- **外观：已验证。** 把 RGBA 导出来分别叠在浅色和深色底上看过：两只气泡有清晰分隔缝，
  「A」「文」镂空可读，深色底上自动反白。
- **菜单栏实景：没验成。** 这台机器的菜单栏被 iStat 那排读数占满，macOS 把我们的图标
  挤到了屏幕外（AX 报的位置是 -3722，典型的"被隐藏"坐标）。**换一台菜单栏不拥挤的
  机器、或临时关掉几个菜单栏应用才能看到实景。**

## 追加（2026-08-20 晚）：用户重做了图标，随之发现真实尺寸下的问题

用户把整套图标换成了新设计（深色圆角底 + 薄荷色选区条 + `A→文` + 角标）。
大尺寸很好看，但**按真实托盘尺寸渲出来一看，小尺寸下信息全丢了**：

- Linux 的 ksni 把彩色 SVG 光栅化到 22/32/48/64 四档。22px 那档：外层 8/128 的安全边距
  吃掉两侧各 1.4 像素，选区条里三个字形总共只剩约 12 个物理像素 —— **平均每字 4 像素**，
  「文」必然糊成一团，四角括号退化成噪点。
- 单色版在 22pt 下：角标 `stroke-width: 1` 折算不到 1 像素、跟选区条粘连；
  箭头镂空 `1.5` 抗锯齿后成灰边而不是干净的洞。

### 改法（两条都做了）

1. **简化单色版**：去掉角标（不是调细 —— 那个尺寸下它只能是噪点）、箭头镂空加粗到
   `2.5`（22pt 下约 2.3 像素）、选区条加高到 12 给箭头留净空。
2. **新增 `data/tray-small.svg`**，Linux 托盘 22/32 两档改用它：去掉安全边距（面板自己
   会留白）、去掉角标和字形，只留「选区条 + 箭头」母题 —— 和菜单栏那份单色图同构，
   两个平台的托盘看起来是同一个东西。48/64 仍用应用图标本身。

### 顺带的重构

两处光栅化（Linux 的 `render_one`、mac 的 `mono_rgba`）合并成模块级的 `rasterize()`，
之后各自重排通道（SNI 要大端 ARGB，Tauri 要 RGBA）。**这不只是去重**：合并之后
`SMALL` 这份 Linux 专属的资源才能在 mac 上被单测覆盖，否则它就是一段谁也验不了的东西。

测试从 `imp` 内挪到模块级，覆盖三份图，尺寸取**真实使用尺寸**（22 / 44）而不是随便挑 ——
放大图上什么都好看，问题只在真实尺寸下暴露。三条断言：三份图都画得出内容、
单色图的箭头必须是镂空的、小尺寸图在 22px 下箭头仍是可辨的镂空（用选区条亮像素占比
卡上下界，防止后来改动把箭头调回细线）。

测试数 31 → 33。

### 验证

真实尺寸（22px）逐格对照渲图确认：新旧差异明显，新版在浅色/深色菜单栏和 Linux 面板
底色上都读得清。托盘注册冒烟通过。
