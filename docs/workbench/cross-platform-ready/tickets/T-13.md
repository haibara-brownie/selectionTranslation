新用户装完不知道怎么用 —— 尤其**三个平台的快捷键不一样**（Linux `Mod+Shift+T`、
mac `⌥⇧T`、Windows `Alt+Shift+T`），而且现在还能自己改。装完没人告诉他按什么。

在弹窗里加一层首次使用提示，带「我会用」关掉。

## 已定的设计约束（动手前先读这几条）

1. **快捷键必须取自后端**，不能在前端写死文案。三平台不同、用户还能改 ——
   一份说谎的教程比没有更糟。所以走 `UiState.hotkeys`（已经加好了）。
2. **不做成模态，不能挡住翻译**。翻译在底下照常跑，点掉「我会用」立刻能看到结果。
3. **只出现一次**，`onboarded` 落进配置。
4. 一个供应商都没配时（`UiState.configured == false`），第一句该说「先去设置里加一个」，
   而不是罗列快捷键 —— 那时候按快捷键也没用。

## ✅ 已完成（2026-08-20 下班前，已提交，全绿）

**后端全做完了**，但前端还没用它，所以这些字段目前是**惰性的**，不影响现有行为：

| 位置 | 加了什么 |
|---|---|
| `config.rs` | `Config.onboarded: bool`，`#[serde(default)]` 缺省 false |
| `state.rs` | `UiState.onboarding: bool`（= `!cfg.onboarded`）、`UiState.hotkeys: (String, String)` |
| `cmds.rs` | `dismiss_onboarding()` 命令，把 `onboarded` 置 true 并落盘 |
| `main.rs` | 命令已注册进 `invoke_handler` |

`onboarded` 缺省 false 是有意的：**老配置升上来也会看到一次**，因为三平台的默认快捷键
在这一轮改过，老用户同样需要被告知。

**前端做了一半**：把 `formatShortcut` / `codeToKey` 从 `dom.ts` 抽成了独立的
`ui/lib/keys.ts`（`dom.ts` 已改成从那儿 import）。抽出来是因为**两个窗口都要用**：
设置页录制快捷键、弹窗显示快捷键；留在 `dom.ts` 里的话，弹窗为了一个格式化函数
得把整套设置页控件拖进包里。这一步是纯重构，`pnpm build` 通过。

## ✅ 已完成（2026-08-20 晚，Arch 侧收尾）

三处都做完了，实机验收通过。做的时候多加了一条后端字段，见文末。

### 原计划（保留作对照）

### 1. `ui/index.html` — 加一层覆盖

在 `.shell` 里、`.content` 之后加一个默认 `hidden` 的容器，例如：

```html
<div id="onboard" class="onboard" hidden>
  <div class="onboard-card">
    <h2>怎么用</h2>
    <ul id="onboard-tips"></ul>
    <button id="onboard-ok" class="onboard-ok">我会用</button>
  </div>
</div>
```

条目文字由 JS 填（因为要插入真实快捷键），不要写死在 HTML 里。

### 2. `ui/popup.ts` — 渲染与关闭

- 本地那个 `type UiState` 是手写的字面量类型，**要补上两个新字段**：
  `onboarding: boolean` 和 `hotkeys: [string, string]`，否则 `tsc --noEmit` 过不了。
- `renderState()` 里：`s.onboarding` 为真就填内容并显示。
- 文案按 `s.configured` 分两种：
  - **没配供应商**：第一条写「先按 <设置快捷键> 打开设置，加一个模型供应商」
  - **配好了**：罗列 —— 选中文字按 <翻译快捷键>；直接在上面输入框敲字 `Ctrl+Enter` 翻译；
    顶部换风格、底部换模型，换完自动重译；`Esc` 收起；托盘图标左键开输入框、中键翻译选中
- 快捷键用 `formatShortcut(s.hotkeys[0], isMac)` 排版，`isMac` 可以用
  `navigator.platform`/`userAgent` 判，或者更稳的办法是让后端多给一个 `os` 字段
  （`settings_cmds::platform` 已经有这个能力，设置页走的是 `ctx.os`）。
- 「我会用」→ `await invoke("dismiss_onboarding")` → 把覆盖层 `hidden = true`。
  失败也要关掉界面上的这一层（不能因为写配置失败就让用户一直看着它），
  只在状态栏提一句。

### 3. `ui/style.css` — 样式

跟着现有的动效语汇走（`shell-in` / `combo-in` 那几个 keyframes 的时长和缓动）。
覆盖层建议半透明底 + 居中卡片，**别铺满整个窗口**，让用户能瞥见底下的译文已经出来了。

## 验收

- 全新配置（`onboarded` 缺省 false）下打开弹窗，提示出现，快捷键显示的是**本平台**的
- 一个供应商都没配时，第一条是引导去设置，不是罗列快捷键
- 点「我会用」后消失；重开弹窗不再出现（`~/Library/Application Support/seltrans/config.json`
  里 `onboarded` 变成 true）
- 把 `onboarded` 手动改回 false、再改一个自定义快捷键，重开弹窗，
  提示里显示的是**改后的键**（这条是约束 1 的验收）
- 翻译在提示盖着的时候照常跑完，点掉就能看到结果

## 想验但本机验不了的

弹窗里的按键捕获/点击没法从 AppleScript 稳定驱动（`click at` 进不去 WKWebView，
Tab 序也够不到）。**用 `popup --input` 进焦点链**，从原文框 Tab 过去 —— 手法见
`spec.md` 的「Mac 侧攒下的验证手法」。

## 实际做了什么（Arch 侧收尾）

三处按计划做了，另外**多加了一条后端字段**：

| 位置 | 改动 |
|---|---|
| `state.rs` | `UiState.os: String` —— 快捷键排版要分平台（mac 连写 ⌥⇧T，另两家用加号），提示里「托盘 / 菜单栏」的措辞也分平台 |
| `index.html` | `#onboard` 覆盖层，条目由 JS 填 |
| `popup.ts` | `UiState` 补三个字段、`renderOnboarding()`、`dismissOnboarding()`、Esc 优先收提示 |
| `style.css` | `.onboard` / `.onboard-card` / `kbd` / `.btn-primary` + 两个 keyframes |

**为什么加 `os` 而不是用 `navigator.platform`**：票里给了两个选项，选后端是因为
`navigator.platform` 已废弃、拿 `userAgent` 猜平台不可靠；而且弹窗启动路径上多一次
IPC 往返（走 `settings_cmds::platform`）就多一分肉眼可见的延迟 —— 划词翻译最忌讳这个，
跟着 `UiState` 一起给是零成本。

### 两个计划外的修正

1. **`.shell` 原本没有 `position: relative`。** 覆盖层是绝对定位的，没有定位上下文
   它会挂到视口上，于是 `.shell` 的 `overflow: hidden` 裁不住它 —— 罩子会把窗口的
   圆角画成方角（Linux / Windows 上窗口透明圆角，一眼能看出来）。
2. **`.onboard[hidden]` 要显式写 `display: none`。** `.onboard` 的 `display: flex`
   是作者样式，优先级压过 `[hidden]` 的浏览器默认规则；不写这条 `hidden = true`
   设了等于没设。设置页的 `.row` 踩过同一个坑，这次直接一起写上。

### Esc 的处理

提示盖着时 Esc **先收提示、不关窗** —— 用户这时候多半是想看底下已经翻好的译文，
而不是把窗口关掉重来。收完提示再按才是关窗。
