Windows 目前**只有模拟 Ctrl+C 一条路**，是三平台里最弱的一环。
参考 Cherry Studio：他们在 Windows 上走 UI Automation + IAccessible + 低级鼠标/键盘钩子，
剪贴板模拟只是兜底。

改成：**UIA 首选 → Ctrl+C 兜底**。

## 必须守住的既有约定

- 抬修饰键那一批事件仍要一次 `SendInput` 发完（约束 4，且 enigo 做不到，所以 Windows
  这边没用 enigo）
- 「Ctrl+C 到底有没有生效」仍靠 `GetClipboardSequenceNumber` 判断，不比对内容

## 已知限制（Cherry Studio 踩过的，可直接借鉴）

JetBrains IDE、Excel/PowerPoint、PDF 阅读器、游戏模式、传统控制台（Ctrl+C 是中断信号）、
UIPI 挡提权窗口。

**注意**：本机（mac）连交叉类型检查都做不了（`aws-lc-sys` 要能编 Windows 的 C 工具链），
只能靠 CI 和用户的 Windows 机器验。写的时候留足日志。

**验收**：用户在 Windows 上按顺序试记事本 / Chrome / VS Code / Word，日志显示 UIA 命中或
正确降级；剪贴板还原正确。
