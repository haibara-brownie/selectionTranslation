默认键写死就一定会撞上某些用户的既有绑定（Bob / Raycast / 输入法等）。
撞上时 `register` 返回 Err、程序照常跑，但**用户没有任何办法改**。

需要：config 加字段、设置界面加录制控件、改完重新注册、撞车时给出可见反馈。

Linux 分支不适用——那边快捷键归合成器，改 `~/.config/niri/selectiontranslation.kdl`。
设置界面在 Linux 上应当说明这一点而不是给一个改不动的控件。

**验收**：mac/Windows 上能改键并立即生效；改成已被占用的组合时界面明确报错。

## 已完成（2026-08-20）

- `Config` 加 `hotkey_translate` / `hotkey_settings`，**留空表示用内置默认**；
  Linux 上字段照样保留（多机共用一份配置时不被来回覆盖），只是不生效。
- `hotkey.rs`：`configured()` 现读配置（不缓存——改键要立刻重注册，缓存只多一个失效点）；
  `reload()` 先 `unregister_all` 再注册（不撤的话旧组合还占着系统，新旧两套都能触发）；
  `describe()` / `current()` 跟着配置走。
- **回调改成比对解析后的 `Shortcut` 而不是字符串**：用户配出来的写法和 `to_string()`
  归一化之后未必一致（大小写、`Ctrl`/`Control` 别名），比字符串会漏判。
- 命令 `hotkeys()` / `set_hotkeys()`。**刻意不走 `save_config`**：那条路是防抖的
  （250ms 后才写），而改键需要当场知道成不成。`set_hotkeys` 是同步的、带返回值的，
  且**注册失败会把配置回滚**——留着一份注册不上的配置，下次启动照样起不来，
  那时用户已经不记得改过什么了。
- 前端 `hotkeyRow`：点一下进入录制，按下组合即提交，**要求至少一个修饰键**
  （允许把单个字母注册成全局键，等于让用户一按那个字母全世界都收不到）。
  mac 上显示成 `⌥⇧T` 这种符号写法。带「默认」重置。
- Linux 分支保持原样：列出 niri 提供的按键 + 说明为什么改不了。

### 验证状态

- **配置驱动注册：已验证。** 写入 `Control+Alt+J` / `Control+Alt+K` 后重启，
  日志显示按自定义键注册，`--help` 的描述也跟着变。
- **非法配置的降级：已验证。** 写入 `ThisIsNotAKey` 后：干净报警并指名是哪个值、
  托盘照常注册、进程存活、`translate` 子命令仍然可用。
- **界面渲染：已验证**（截图：`⌥⇧T` / `⌥⇧,` + 「默认」链接 + 说明）。
- **浏览器里的按键捕获：没摆拍成。** webview 内的焦点链没法从 AppleScript 稳定驱动
  （`click at` 进不去 WKWebView，Tab 序也够不到那两个按钮）。捕获逻辑是纯前端的
  `keydown` → `e.code` 映射，风险低，但**没有实测过**。
